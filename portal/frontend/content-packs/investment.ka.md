## Block: section
id: solution
title: What we are building
lead: ორი დამოუკიდებელი ძრავა, ერთი მეთოდი: ღირებულება მხოლოდ სამუშაოს დადასტურების შემდეგ აღიარდება, და ყოველი მნიშვნელოვანი მდგომარეობა აღირიცხება.
* **Aros Studio Tokenomics (AST)** — შესრულებისა და აღრიცხვის ძრავა. ის უკვე დადასტურებულ ინსტიტუციურ შეფასებებს უფლებების ტოკენებად აღრიცხავს, ყოველ პროცესს Proof of Transaction-ით ადასტურებს და NodeChain-ზე მხოლოდ დასამატებელ ჩანაწერს აწარმოებს.
* **Aros Financial Core (AFC)** — AST-სა და ლიცენზირებულ ანკერებს შორის ერთი API კონტრაქტის შესრულების პროცესი, რათა ავტორიზებული მოთხოვნა ერთ სისტემაში დაიწყოს და მეორეში დასრულდეს ისე, რომ მეურვეობა არავინ აიღოს.
- N×N ორმხრივი ინტეგრაციის ნაცვლად, ყოველი ინსტიტუცია ერთხელ ინტეგრირდება ერთ კონტრაქტთან. თითოეული საკუთარ ლიცენზიას, სისტემებსა და რეგულატორს ინარჩუნებს.

## Block: section
id: model
title: Business model
* **პროცესის საკომისიო** — მცირე საკომისიო დადასტურებული პროცესების მოცულობიდან, რომელიც მხოლოდ პროცესის დადასტურებისას ირიცხება. ის ნაწილდება იმ ინფრასტრუქტურულ კვანძებს, რომლებმაც სამუშაო შეასრულეს, და AST-ის საკუთარ რეზერვს შორის.
* **ინტეგრაცია და API ლიცენზირება** — ინსტიტუციური წვდომა API კონტრაქტზე, ინტეგრაციის მხარდაჭერა და სენდბოქს გარემოები.
* **პილოტები და პროგრამები** — განსაზღვრული ფარგლების პილოტები და აუდიტზე ორიენტირებული პროგრამები საჯარო სექტორისა და განვითარების ფინანსების კლიენტებისთვის.
- შემოსავალი დადასტურებულ მოცულობასთან ერთად იზრდება და არა ტოკენების ფასთან. გასაყიდი ტოკენების ხაზინა და წინასწარი გამოშვება არ არსებობს.

## Block: section
id: status
title: Where we are today
* **AST Core** — კანონი რატიფიცირებულია (2026 წლის ივლისი); ძირითადი ძრავა გამოშვებულია 1.0–1.2 ვერსიებად. ვერსია 1.2 (2026 წლის ივლისი) პილოტისთვის მზა საბაზისო ვერსიაა Proof of Transaction-ით, NodeChain ჟურნალით, ორკესტრატორითა და ინსტიტუციების ავთენტიფიკაციით. გარე აუდიტი და მრავალკვანძიანი საწარმოო დანერგვა ჯერ კიდევ წინაა.
* **ინსტიტუციური პორტალი** — მოქმედებს: საჯარო პროცესების მკვლევარი, NodeChain ჟურნალი და ინსტიტუციის კაბინეტი დოკუმენტზე ორიენტირებული ოსტატით, ხელმოწერის ატესტაციითა და QR-ით გადამოწმებადი სერტიფიკატებით. ინგლისური, რუსული და ქართული ინტერფეისები.
* **AFC** — API კონტრაქტის სპეციფიკაცია v3.0.0 მომზადებულია (2026 წლის ივლისი) და განხილვის პროცესშია.
* **ინტელექტუალური საკუთრება** — აშშ-ის წინასწარი საპატენტო განაცხადი შეტანილია 2025 წლის აგვისტოში (Modular Architecture for Hybrid Transactional Systems).
* **შემდეგი ნაბიჯი** — AST-ის ჰოსტინგზე დანერგვა და ბოლომდე გავლილი პილოტი ხელმოწერით, რასაც პირველი მარეგულირებელი სენდბოქსი მოჰყვება.

## Block: section
id: risks
title: Risks we take seriously
- სერიოზული ინვესტორები პირველ რიგში რისკებზე კითხულობენ, ამიტომ მათ პირდაპირ ვასახელებთ.
* **მარეგულირებელი** — მოთხოვნები იურისდიქციების მიხედვით განსხვავდება და ციფრული აქტივებისთვის ჯერ კიდევ ვითარდება. ჩვენ ყველაზე მკაცრი ინტერპრეტაციისთვის ვაპროექტებთ და ყოველ დანერგვას ადგილობრივ იურისტთან ვადასტურებთ.
* **დანერგვა** — ინსტიტუციები ფრთხილად მოძრაობენ. ჩვენი შესვლის წერტილი ყველაზე დაბალი რისკის შემთხვევაა: აუდიტზე ორიენტირებული ჩანაწერები ფულის გადაადგილებამდე.
* **კონკურენცია** — არსებული ქსელები და ცენტრალური ბანკების პროექტები საკუთარ ორკესტრაციის ფენებს აშენებენ. AFC შექმნილია მათ გარე საზღვრებზე სამუშაოდ, სადაც ნეიტრალური კოორდინაცია ჯერ კიდევ არ არსებობს.
* **შესრულება** — ჩვენ ვაქვეყნებთ ჩვენს კანონს, ინვარიანტებსა და ავტომატურ დამცავებს, რათა პროგრესის შემოწმება შესაძლებელი იყოს და არა მხოლოდ მისი განცხადება.
